# Дизайн-документ: Anki English Web App с синхронизацией через GitHub API

## 1. Контекст и цели
Персональное мобильно-адаптивное веб-приложение для запоминания английских слов по методу карточек Anki. Приложение размещается на GitHub Pages как статический сайт. Пользователь может вставлять новые пачки слов в формате JSON прямо в браузере, после чего приложение автоматически обновляет словарь `words.json` в репозитории проекта на GitHub через REST API.

### Цели
- **Интерактивные карточки Anki:**
  - Лицевая сторона: английское слово/фраза.
  - Обратная сторона: русский перевод.
  - Переворот карточки по тапу/клику или клавише Space/Enter.
  - Навигация: «Следующая», «Предыдущая», «Случайная» (Shuffle).
  - Счётчик прогресса текущей сессии (текущий индекс / всего слов).
- **Импорт новых слов (JSON):**
  - Поддержка формата `[{"en": "clean", "ru": "чистый"}, ...]`.
  - Валидация входного JSON с защитой от синтаксических ошибок.
  - Автоматическая нормализация (trim, case-insensitive проверка дубликатов по полю `en`).
  - Отображение превью перед отправкой (сколько слов найдено, сколько дубликатов отсеяно).
- **Синхронизация через GitHub Contents API:**
  - Прямой коммит обновленного `words.json` в репозиторий через GitHub REST API (`PUT /repos/{owner}/{repo}/contents/{path}`).
  - Получение актуального `sha` файла перед коммитом для предотвращения конфликтов.
  - Безопасное хранение GitHub Personal Access Token (PAT), владельца и репозитория исключительно в `localStorage` браузера пользователя.
- **Оффлайн/Резервный режим:**
  - Если токен не задан, загружается базовая версия `words.json` из репозитория.
  - Новые слова сохраняются в `localStorage`, доступна кнопка «Экспорт words.json» для скачивания файла вручную.
- **Адаптивность и мобильный UX:**
  - Touch-friendly дизайн с крупными элементами управления.
  - Поддержка темной и светлой темы (или нейтральная аккуратная темная тема по умолчанию).
- **CI/CD:**
  - Автоматическая сборка и публикация на GitHub Pages через GitHub Actions workflow.

### Не-цели (Non-Goals)
- Серверный бэкенд, базы данных PostgreSQL/MySQL или внешние серверы аутентификации.
- Сложный алгоритм долгосрочного интервального повторения SM-2 с хранением истории ответов за годы (достаточно легковесного счетчика сессии).
- Многопользовательский режим с разграничением прав.

### Анти-цели (Anti-Goals)
- Хранение секретов или токенов в кодовой базе репозитория или коммитах.
- Использование тяжелых монструозных фреймворков; сборка должна быть максимально легковесной и быстро стартовать в браузере.

## 2. Архитектурные подходы

Рассматривались три варианта хранения словаря:
1. **GitHub Contents API (Выбран):**
   - Пользователь сохраняет персональный токен (PAT) с правами `contents:write` в настройках сайта.
   - Сайт напрямую отправляет коммит с обновленным `words.json` в ветку репозитория.
   - *Плюсы:* единая база слов синхронизирована между смартфоном и компьютером; версионирование в git; слова не теряются при очистке кэша браузера.
   - *Минусы:* требуется сгенерировать GitHub PAT.
2. **GitHub Gist API:**
   - Хранение словаря в отдельном Gist.
   - *Плюсы:* изолированные права токена (`gist`).
   - *Минусы:* отрыв данных словаря от репозитория проекта.
3. **LocalStorage + ручной экспорт:**
   - Сохранение только в браузере с кнопкой скачивания файла.
   - *Плюсы:* токен не нужен.
   - *Минусы:* нет синхронизации между мобильным устройством и ПК.

## 4. Спецификация API и Моделей данных

### 4.1 Формат словаря (`words.json`)
```json
[
  { "en": "clean", "ru": "чистый" },
  { "en": "improve", "ru": "улучшать" }
]
```

### 4.2 Модель настроек (`localStorage`)
Ключ: `anki_config`:
```typescript
interface AppConfig {
  githubToken?: string;
  repoOwner?: string;
  repoName?: string;
  branch?: string;
  filePath?: string; // по умолчанию "public/words.json"
}
```

### 4.3 Механизм обновления через GitHub Contents API
1. Запрос `GET https://api.github.com/repos/{owner}/{repo}/contents/{filePath}?ref={branch}` с заголовком `Authorization: Bearer {token}`:
   - Получение текущего SHA файла и актуального содержимого.
2. Слияние существующих записей с новыми:
   - Приведение `en` к lowercase и trim для выявления дубликатов.
   - Добавление уникальных новых пар в конец массива.
3. Запрос `PUT https://api.github.com/repos/{owner}/{repo}/contents/{filePath}`:
   - Тело:
     ```json
     {
       "message": "feat: update words dictionary via web app",
       "content": "<base64_encoded_utf8_json>",
       "sha": "<file_sha>",
       "branch": "{branch}"
     }
     ```
4. Обновление локального состояния приложения новым списком слов без перезагрузки страницы.

## 5. UI/UX Спецификация
1. **Главный экран:**
   - Шапка: название, кнопка «Перемешать», кнопка «+ Добавить слова», иконка «Настройки».
   - Центр: карточка фиксированного адаптивного размера (макс. ширина 460px, пропорции 3:2).
     - 3D-переворот по клику/тапу.
     - Лицевая сторона: крупный текст на английском, подпись «Нажмите для перевода».
     - Обратная сторона: русский перевод.
   - Панель управления снизу:
     - Кнопка «Назад» (стрелка влево).
     - Индикатор прогресса (`X / Y`).
     - Кнопка «Вперед» (стрелка вправо).
     - Кнопка «Случайная» или «Перевернуть».
2. **Модальное окно импорта:**
   - Текстовое поле ввода (Textarea) с placeholder формата JSON.
   - Кнопка «Валидация»: отображает статус (найдено слов, дубликатов).
   - Кнопка «Сохранить и отправить в GitHub»:
     - Если настроен PAT: отправка через GitHub API со спиннером загрузки.
     - Если PAT не настроен: сохранение в кэш браузера и предложение скачать `words.json`.
3. **Модальное окно настроек:**
   - Поля: GitHub Personal Access Token, Репозиторий (например `username/anki-english`), Ветка (`main`), Путь к файлу (`public/words.json`).
   - Кнопка проверки соединения (`Test Connection`).
   - Кнопка сохранения.

## 6. Что отдается на усмотрение разработчика

- Клавиатурные сочетания (стрелки влево/вправо для навигации, пробел для флипа).
